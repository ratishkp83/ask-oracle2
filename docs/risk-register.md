| RISK-12 | Permissive CORS `*` + credentials + `0.0.0.0` bind (pre-existing); unauthenticated `/health` + `/metrics` | Medium | Cross-origin/SSRF amplification once exposed/multi-tenant; `/metrics` exposes aggregate counts only (no data/secrets) | Low | **Closed at the app layer** (Phase 6.5/B1, [ADR-013](adr/ADR-013-network-edge-hardening.md), **ITM-009 closed**): opt-in `X-API-Key` auth (`/health` exempt, `/metrics` gated) + explicit `ALLOWED_ORIGINS` (no `*`+credentials possible); D7 §2 network-exposure rule covers the bind. Residual: operator must set `APP_API_KEY` before exposure (deployment discipline, not code) | Eng | **Closed** |
| RISK-13 | Parameterized reports could re-introduce SQL injection / SELECT-only bypass | High | Read-only guarantee defeated via parameter values | Low | **Bind variables only**, never interpolated ([ADR-007](adr/ADR-007-parameterized-reports-bind-variables.md)); `validate_binds` (scalar-only); SQL-text safety check unchanged + runs first; 11 bind-safety tests (injection-as-value inert; DML-with-binds rejected) | Eng | **Mitigating** |
| RISK-14 | EBS templates assume a standard schema; may fail/mislead on customized instances | Low | Template run errors or wrong results on customized EBS | Medium | Labelled "standard EBS reference — review before running"; editable; never auto-run; live-EBS validation deferred to pre-GA pass ([RISK-04](#)) / [ITM-012](issue-log.md) | Product/Eng | **Accepted** |
| RISK-15 | A SELECT can invoke a side-effecting / autonomous-txn PL/SQL function (parse gate can't prove side-effect-freedom) — F1 | High | "No data modification" guarantee defeated *iff* a writing function + EXECUTE grant exist on the connected account | Low | **Defense in depth:** SELECT/CTE-only parse gate (ADR-001) + bind params (ADR-007) **and a required least-privilege read-only DB account** ([ADR-009](adr/ADR-009-readonly-db-account-precondition.md), [Deployment §0](07-deployment-plan.md)) — the account, not parsing, is the control. Optional parse-time package denylist available as extra defense-in-depth (owner decision; not enforced) | Eng/Ops | **Mitigating** |
| RISK-16 | File-store durability/concurrency: non-atomic writes + per-process lock (R1) | Low | Torn `reports.json`/`profiles.json`/`schemas.json` on crash; lost updates with >1 worker | Low | **Durability closed** (Phase 6.5/B3-B4, [ADR-014](adr/ADR-014-file-store-durability.md), **ITM-013/014 closed**): atomic temp+fsync+`os.replace` in all 4 stores + corrupt-record quarantine (skip-and-log, preserve-on-save). **Concurrency residual accepted:** one worker per store directory is the documented D7 constraint; SQLite if multi-worker is ever planned | Eng | **Mitigating** (concurrency residual accepted) |
| RISK-17 | Introspecting a huge catalog (EBS) overwhelms UI / times out | Medium | Slow/blocked introspection; truncated dictionary | Low | **Scoped** (owner + name filter required/encouraged) + **capped** by `SafetyLimits` (`truncated` surfaced); on-demand, no full crawl ([ADR-010](adr/ADR-010-schema-introspection-via-chokepoint.md)) | Eng | **Mitigating** |
| RISK-18 | Persisted schema metadata sensitivity (table/column names) | Low | Local-file exposure of business metadata (no data values/creds) | Low | `schemas.json` is metadata only, git-ignored under `STORAGE_DIR` like profiles/reports | Eng | **Accepted** |
| RISK-19 | Information disclosure via verbatim DB-driver errors (DSN/host/port/username) to the client (ITM-015) | Medium | Infrastructure detail leaked to API/UI callers | Low (local posture) | **Resolved (Phase 6):** uniform sanitization — generic message + `error_id` to the client, full detail logged server-side only ([ADR-012](adr/ADR-012-observability-and-error-handling.md)); shared by API + UI; leak-proof test | Eng | **Closed** |
| RISK-20 | Email follow-up action (Phase 8) transmits row data to an external recipient — a deliberate egress | Medium | Sensitive report output sent outside the org / to a wrong or personal address | Low | **User-initiated + reviewed** — same trust boundary as the existing CSV/Excel export, never auto-sent; **every send audit-logged** (`ask_oracle.audit`, metadata only — no body, no row data, no credential); **optional `EMAIL_ALLOWED_DOMAINS` allow-list**; feature **opt-in** (off unless SMTP configured); **no LLM** on the path ([ADR-017](adr/ADR-017-email-report-via-gmail-smtp.md)) | Product/Eng | **Mitigating** |
| RISK-21 | Gmail App Password (SMTP credential) exposure via logs / API responses / return values | High | Mailbox compromise; send-as abuse | Low | **Env-only**; reaches only `smtplib.login`; **never** placed in a `SendResult`, audit field, log record, or any return; transport errors sanitized (generic + `error_id`, ADR-012 pattern); not written to any store; opt-in gate ([ADR-017](adr/ADR-017-email-report-via-gmail-smtp.md)) | Eng | **Mitigating** |
| RISK-23 | Profiling load on the client's production DB (P11-R1) | Medium | Onboarding profiling hammers a production OLTP box | Low | Catalog-only by default; live `COUNT`/value sampling **opt-in + bounded** (`SAMPLE`/row caps); SELECT-only through the chokepoint; privilege-degrading ([ADR-028](adr/ADR-028-database-profiling.md)) | Eng | **Mitigating** |
| RISK-24 | Ephemeral async job + result cache hold row data in process memory (P11-R2) | Medium | Result data resident in memory beyond the request | Low | **Memory-only**, short TTL, size-capped, per-profile keys, **no disk persistence**; resets on restart ([ADR-030](adr/ADR-030-resilient-async-execution.md)) | Eng | **Mitigating** |
| RISK-25 | Enriched metadata / value domains could leak row-derived values to the LLM (P11-R3) | High | Invariant-3 breach (values to a model) | Low | **Two-channel split** — Channel B (values/semantics) is physically unreachable from `build_external_context`; only Channel A names/magnitudes are sent; `assert_no_values` tripwire; dedicated leak test ([ADR-028](adr/ADR-028-database-profiling.md)/[ADR-029](adr/ADR-029-plan-aware-generation.md)) | Eng | **Mitigating** |
| RISK-26 | Async cancel may not stop the in-flight DB query (P11-R6) | Medium | Orphaned long query keeps consuming client resources | Low | `conn.call_timeout` hard backstop bounds every call; explicit `conn.cancel()` best-effort; bounded async timeout ([ADR-030](adr/ADR-030-resilient-async-execution.md)) | Eng | **Mitigating** |
| RISK-27 | Mandatory setup-readiness gate blocks legitimate onboarding (P11-R11) | Medium | A connection that can't read catalog views / has no declared FKs is hard-blocked | Low | "Mandatory" = **capture-or-explicitly-resolve** at the gate, never invent data; **soft-block default** (usable, flagged "Not optimized"), hard-block opt-in; manual-provision path (charter D-L) | Eng | **Mitigating** |
| RISK-22 | React surface egresses result data over the API — `/execute` returns rows to a browser client, and `/reports/export` + `/reports/email` receive the already-shown rows back ([ADR-019](adr/ADR-019-react-cxo-surface.md), [ADR-020](adr/ADR-020-result-export-and-email-api.md)) | Medium | Report data in transit / resident in a browser tab (vs Streamlit's server-side render) | Low (local/same-origin beta) | **No new disclosure** beyond what `/execute` already returns to its caller; the React app holds **no DB secrets** (connections by `profile_id`, invariant 4) and **persists no result data** (rows live only in component state, gone on reload — only the chosen `profileId`/`schemaId`/`autoRun` are stored). **No row data to any LLM** (all derivation local, [ADR-021](adr/ADR-021-sql-aware-derivation-and-cascade.md)); export/email reuse the Phase-8 guards + metadata-only audit ([ADR-020](adr/ADR-020-result-export-and-email-api.md)). Networked deployments gate the API (opt-in `X-API-Key` + explicit CORS, [ADR-013](adr/ADR-013-network-edge-hardening.md)) and must serve over **HTTPS** (D7); same-origin dev proxy in beta | Eng | **Mitigating** |
